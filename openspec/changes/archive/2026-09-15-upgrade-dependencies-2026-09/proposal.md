## Why

The reactor's third-party versions have drifted behind upstream, and the drift is now load-bearing rather than cosmetic. The OpenFeature SDK is pinned at `1.15.1` while the contrib provider BOM (`dev.openfeature.contrib:openfeature-contrib:1.0.0`) and individual providers have moved to a generation that requires the SDK in the `[1.16.0,1.99999)` window — and `flagd`/`go-feature-flag` specifically require `[1.21.0,…)`. Because `spring-openfeature/pom.xml` pins the SDK explicitly, provider ranges do not raise the runtime SDK on their own, so the SDK and every provider must move together or risk an uncaught `NoSuchMethodError`/NPE at runtime (compilation will not catch a signature drift inside this window). Independently, two provider majors sit behind (configcat `0.1.0`→`0.2.1`, go-feature-flag `0.4.3`→`1.2.1`, the latter flipping the default evaluation mode to in-process WASM), the Unleash client is 11→12, and the build's JDK posture is ambiguous (the Debian `java-17-openjdk` package is a JRE with no `javac`/`javadoc`).

This change brings the dependency and build-plugin set to a single, coherent, CI-verifiable baseline and records the deliberately-deferred items so the upgrade can be landed and reviewed as one unit.

## What Changes

- **OpenFeature lockstep bump (one atomic change):** raise `sdk.version` `1.15.1`→`1.22.1` and move all contrib providers to their latest compatible release together — `flagd` `0.11.15`→`0.14.1`, `go-feature-flag` `0.4.3`→`1.2.1` (**BREAKING** — default `EvaluationType` becomes `IN_PROCESS`/WASM), `configcat` `0.1.0`→`0.2.1`, `flipt` `0.1.1`→`0.1.4`, `jsonlogic` `1.2.1`→`1.3.0`; `env-var`/`flagsmith`/`multiprovider`/`statsig`/`unleash`(provider)/`growthbook`(provider) are already at latest and stay. Rationale and the compatible set are pinned in `design.md`.
- **Two required test fixes ride with the lockstep bump** (both are runtime, not compile):
  - `MultiProviderAutoConfigurationTest` — stop `Mockito.mock(MultiProvider.class)`; under SDK `≥1.21` the mocked `EventProvider` skips its constructor so the `attachment` `AtomicReference` is null and `EventProvider.attach` NPEs. Build a real `new MultiProvider(List.of(), new FirstMatchStrategy())` (or an `EventProvider` stub) instead.
  - `GoFeatureFlagAutoConfigurationTest` — a bare `MockWebServer` never answers `/v1/flag/configuration`, so the 1.x default in-process provider hangs the build. Force `EvaluationType.REMOTE` via a `GoFeatureFlagCustomizer`, or stub the OFREP/WASM endpoints.
- **Build-plugin hygiene (behavior-preserving):** bump `jacoco-maven-plugin` `0.8.14`→`0.8.15`, `maven-compiler-plugin` `3.14.1`→`3.16.0`, `versions-maven-plugin` `2.20.1`→`2.21.0`, `flatten-maven-plugin` `1.7.3`→`1.8.0`, `maven-gpg-plugin` `3.2.7`→`3.2.8`, `central-publishing-maven-plugin` `0.8.0`→`0.11.0`, and the Checkstyle library `com.puppycrawl.tools:checkstyle` `10.21.4`→**`12.3.1`** (amended: the drafted `14.1.0` target is not adoptable on this JDK 17 build — the whole `13.x`/`14.x` line is class-file major 65/Java 21 and dies with `UnsupportedClassVersionError`; `12.3.1` is the newest loadable release. See `design.md` Decision 7 and tasks 2.2; `pom.xml` pins `12.3.1`).
- **Examples reactor:** bump `springdoc-openapi-starter` `2.8.4`→`3.1.1` (**BREAKING** major, the Boot-4 line) so the examples resolve the locally-built `4.1.0-SNAPSHOT` starter rather than a stale artifact. (Amended: the drafted `-Dspring-boot-openfeature.version=4.1.0-SNAPSHOT` override was dropped — the examples derive the version from their own `${revision}`, and the override drove `flatten` `updatePomFile=true` to rewrite the tracked `examples/pom.xml`; see `design.md` Decision 8 and tasks 4.1.)
- **Unleash client (amended 2026-09-14 — promoted, no longer an unbundled spike).** This bullet drafted `io.getunleash:unleash-client-java` `11.2.1`→`12.3.0` as an optional, isolated spike that "must not be bundled with the core bump." It was ultimately **folded into the branch and promoted to `12.3.0`** (`pom.xml:99`) by direction. Decision 5's original endpoint re-verification gate was found void and replaced by `UnleashEndpointIntegrationTest`, which drives the auto-configured provider against a live Unleash server; that test self-skips without an endpoint, so its green is a locally-recorded run, not CI-enforced. The residual risk stands unchanged: provider `0.1.3-alpha` officially targets client `11.0.2`, so `12.3.0` remains an unsupported pairing whose streaming path is unexercised by any test.
- **Amended 2026-09-14 (was drafted as deferred, now shipped by the §7 upgrade sweep).** This bullet originally recorded OkHttp `4.12.0`→`5.x` and the GrowthBook SDK `0.10.6`→`0.11.0` as "deliberately deferred … blocked on upstream." The 2026-09-12 sweep took every `*.version` property to authoritative latest and **both shipped**: `pom.xml` carries `<okhttp.version>5.5.0` and `<growthbook-sdk-java.version>0.11.0` (the latter a repackaging into a `com.github.growthbook.growthbook-sdk-java:lib` module, the published shell being a 292-byte stub). The `flagsmith` line's OkHttp-4 blocker was **dissolved, not worked around**: `com.flagsmith:flagsmith-java-client` was promoted `7.4.3`→`8.1.1` (an OkHttp-5-native build, via a `flagsmith-java-client.version` property plus a BOM exclusion/re-declaration and a direct module dependency) rather than pinning OkHttp down. The deferral rationale below is kept as history; the authoritative current pins are `pom.xml` and `docs/dependency-versions.md`.

No production source changes; the only source edits are the two test files above.

- **Verify gate:** full `./mvnw -B -Psonar clean verify` on the canonical Azul JDK 17 (`/home/wantez/.jdks/azul-17.0.20.1`), plus targeted `-pl` runs for the two fixed modules and the examples reactor.
