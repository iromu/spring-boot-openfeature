# Provider Starter Contract

The contract every `spring-boot-starter-openfeature-<provider>` module MUST satisfy, stated once. It was previously duplicated as 18 near-identical OpenSpec capability specs; those files are retired and this page is authoritative.

## Scope

This page governs the **18 provider starters** that were specified under OpenSpec:

`ageris`, `cloudbees`, `confidence`, `configdirector`, `datadog`, `devcycle`, `featbit`, `featureflip`, `gcp`, `kameleoon`, `launchdarkly`, `mixpanel`, `octopusdeploy`, `ofrep`, `optimizely`, `split`, `superposition`, `vwo`.

The **11 earlier starters** — `configcat`, `envvar`, `flagd`, `flagsmith`, `flipt`, `gofeatureflag`, `jsonlogic`, `multiprovider`, `statsig`, `unleash`, `growthbook` — follow the same pattern but predate the spec set and are not covered by its wording. For those, the module `README.md` is authoritative.

In all cases the per-module `README.md` remains the source of truth for the full property table, dependency snippet and examples. This page deliberately does **not** reproduce those tables — it links to them. See also [architecture.md](architecture.md) for how a starter fits into the reactor, [quality-and-testing.md](quality-and-testing.md) for the test tiers, [dependency-management.md](dependency-management.md) for version pinning, and [backlog.md](backlog.md) for known gaps.

## Shared contract

A provider starter MUST:

- **Register exactly one provider.** When the provider library is on the classpath and the starter is enabled, the context exposes exactly one `dev.openfeature.sdk.FeatureProvider` contributed by the starter, and one OpenFeature `Client` built on it (`ClientAutoConfiguration` is `@ConditionalOnBean(FeatureProvider.class)` and backs off when a `multiProvider` bean exists).
- **Contribute nothing when the library is absent.** `@ConditionalOnClass` on the vendor provider class means a missing provider jar yields no beans and no startup failure.
- **Offer a declarative off-switch.** `spring.openfeature.<provider>.enabled=false` MUST prevent any `FeatureProvider` contribution, via `@ConditionalOnProperty(prefix = …, name = "enabled", havingValue = "true", matchIfMissing = true)`. Construction that starts vendor machinery MUST NOT happen for a disabled starter.
- **Back off entirely for a consumer provider.** If the consumer defines their own `FeatureProvider` bean, the context ends with exactly that one provider and none from the starter. In practice the starter's configuration/options bean is guarded with `@ConditionalOnMissingBean({ <Provider>Options.class, FeatureProvider.class })` so a consumer provider suppresses option assembly too, and the provider bean itself is `@Bean @ConditionalOnMissingBean`.
- **Configure from properties.** All provider settings bind from `spring.openfeature.<provider>.*` through a `<Provider>Properties` `@ConfigurationProperties` class; unset optional values are left untouched so the vendor builder's own defaults keep applying.
- **Fail fast on missing mandatory input**, naming the exact property path (e.g. `Ageris requires 'spring.openfeature.ageris.path' when 'spring.openfeature.ageris.enabled=true'`) rather than letting the vendor SDK NPE or silently produce an unusable client. Providers with no mandatory inputs (OFREP, Optimizely) perform no such validation.
- **Apply the customizer last.** Every registered `<Provider>Customizer` runs, in `orderedStream()` order, against the assembled vendor configuration/builder *after* property binding and *before* the provider is constructed, so consumer adjustments are observable in the built object.
- **Test credential-free.** The module's auto-configuration contract tests MUST pass on a host with no provider credentials and MUST make no network calls. Tests that do contact a real backend MUST self-skip (not fail) when their gating environment variable is absent.

Provider-specific deviations from this contract are recorded in the last column below. Where a spec and the module code disagree, **the code is authoritative** and the divergence is noted.

## Adding a new provider starter

Replicate the Unleash module (`spring-boot-starter-openfeature-unleash/`) as the reference implementation; the Ageris module shows the same shape with fail-fast validation.

**Module** — new `spring-boot-starter-openfeature-<provider>/`:

- [ ] `src/main/java/org/iromu/openfeature/boot/<provider>/<Provider>Properties.java` — `@ConfigurationProperties(prefix = <Provider>Properties.<PROVIDER>_PREFIX)` with a `PREFIX` constant `spring.openfeature.<provider>`, `enabled = true` by default, and Javadoc on every field (it feeds `spring-configuration-metadata`).
- [ ] `<Provider>Customizer.java` — `@FunctionalInterface` with a single `customize(<vendor config or builder>)`, documented as running before the provider is built.
- [ ] `<Provider>Options.java` (or reuse the vendor config type) — holder for the assembled configuration when the starter needs to pass more than one value to the provider bean.
- [ ] `autoconfigure/<provider>/<Provider>AutoConfiguration.java` — `@AutoConfiguration`, `@AutoConfigureBefore({ ClientAutoConfiguration.class }, name = "org.iromu.openfeature.boot.autoconfigure.multiprovider.MultiProviderAutoConfiguration")`, `@ConditionalOnClass(<VendorProvider>.class)`, `@ConditionalOnProperty(prefix = …, name = "enabled", havingValue = "true", matchIfMissing = true)`, `@EnableConfigurationProperties(<Provider>Properties.class)`; beans:
      - `@Bean @ConditionalOnMissingBean({ <Provider>Options.class, FeatureProvider.class })` for the config/options bean — validate mandatory properties first, then bind, then `customizers.orderedStream().forEach(c -> c.customize(…))`;
      - `@Bean @ConditionalOnMissingBean` returning `FeatureProvider`.
- [ ] `src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` — Apache header + the auto-configuration FQN.
- [ ] `package-info.java` for each package; Apache header on every Java and XML file.
- [ ] `pom.xml` — import `spring-boot-dependencies` and `spring-boot-openfeature-dependencies`, depend on `spring-boot-openfeature-autoconfigure`, the provider library (version-less, BOM-managed), `lombok` (`provided`/`optional`) + `spring-boot-configuration-processor`, `spring-boot-starter-test`; set `<jacoco.instruction.minimum>` to the instruction covered-ratio the module actually achieves (every spec'd starter is at `1.00`; the ratchet never goes down).
- [ ] `src/test/java/…/<Provider>AutoConfigurationTest.java` — `ApplicationContextRunner`-style contract tests for: single provider + `Client`, disabled via property, consumer-provider back-off, mandatory-property fail-fast (asserting the message names the property path), customizer applied. Must pass with no credentials and no network.
- [ ] `README.md` in the house section order: `# spring-boot-starter-openfeature-<provider>` → `## Adding the Dependency` → `## Requirements` (only when an external prerequisite exists, e.g. Datadog's `dd-java-agent`) → `## Configuration Properties` → `## Example Configuration` → `## Usage` → `## Customization`.

**Reactor** —

- [ ] Root `pom.xml`: add `<module>spring-boot-starter-openfeature-<provider></module>` and the provider's version `<property>` (plus separate properties for any SDK declared explicitly, each with a comment saying *why* it is not transitive).
- [ ] `spring-boot-openfeature-dependencies/pom.xml`: managed entry for every coordinate, `${…version}`-driven. Any provider that transitively pulls an older `dev.openfeature:sdk` MUST pin it to `${sdk.version}` — see [dependency-management.md](dependency-management.md) and the SDK/contrib lockstep rule.
- [ ] `examples/<provider>-simple/` — `pom.xml`, `README.md`, `<Provider>Application`, a `<Provider>Controller`, and `Fake<Provider>ProviderConfig` + `Fake<Provider>Provider` gated on `@ConditionalOnProperty(name = "example.fake-provider", havingValue = "true")` so the sample boots with no vendor account; `application.yaml` documents `--example.fake-provider=true`. Register the module in `examples/pom.xml`.
- [ ] Root `README.md` provider table — include the version column.

Verify with `./mvnw -pl spring-boot-starter-openfeature-<provider> -am clean verify` (JDK 17), and with the `sonar` profile so the aggregate coverage report is built.

## Spec-to-code divergences found during consolidation

Recorded so the retired OpenSpec text is not mistaken for the contract:

- **Octopus Deploy** — spec's mandatory properties (`api-key`, `server-url`) do not exist; the module requires `client-identifier` and `product-name`.
- **FeatBit** — spec names only `token`; the auto-configuration also requires `streaming-url` and `event-url`.
- **OFREP / Optimizely** — neither spec carries the "unit tests need no credentials" requirement that the other 16 do, and neither module implements fail-fast validation. The credential-free rule above is inherited from the shared pattern rather than from those two specs.
- Specs are silent on the `@ConditionalOnMissingBean({Options, FeatureProvider})` double-guard and on the `AutoConfigureBefore` name-based ordering against `MultiProviderAutoConfiguration`; both are load-bearing in code and stated in the shared contract above.
